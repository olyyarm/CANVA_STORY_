# Аудит CANVA STORY

Дата аудита: 31 июля 2026 года. Исходная ветка: `main`, коммит `c4e127d`.

## Что есть сейчас

- React 19, TypeScript и Vite 6; состояние хранится локально в `useNodeManagement`.
- Узлы — абсолютные HTML-элементы, связи — SVG-линии, перемещение реализовано собственным хуком.
- Реализованы ввод сценария, ассоциации, генерация сценария и деталей, создание сцен, master prompt и изображение через Pollinations.
- GitHub Pages настроен на базовый путь `/CANVA_STORY_/`; опубликованная версия открывается.

## Основной пользовательский путь

1. Ввести сценарий и необязательный стилистический промпт.
2. Сгенерировать визуальный сценарий.
3. Создать описания героев, локаций и настроения.
4. Создать узлы сцен и master prompt для каждой сцены.
5. При необходимости сгенерировать изображение.

## Найденные проблемы

### Критические

- Без `VITE_MISTRAL_API_KEY` основной сценарий заканчивается системным `alert`; рабочего тестового режима нет.
- Ключ Mistral передаётся в клиентскую GitHub Pages-сборку, поэтому не может считаться секретным.
- Проект не сохраняется: перезагрузка удаляет введённый текст, сгенерированные узлы и их координаты.
- Нет экспорта, импорта, нового проекта и подтверждённого полного сброса.
- Масштабирование и «показать весь проект» отсутствуют, поэтому большой граф быстро становится неудобным.

### Канва и узлы

- Панорамирование написано на глобальных mouse-событиях, пересоздаёт обработчики и оставляет отладочный шум в консоли.
- Перетаскивание не учитывает масштаб (его пока нет) и опирается на DOM-геометрию трансформированного контейнера.
- Новые сцены размещаются одной длинной колонкой; узлы деталей появляются в одной точке и накладываются.
- Выбор узла, удаление и изменение размера отсутствуют; `z-index` временно меняется напрямую в DOM.
- Кнопки внутри узлов защищены от drag частично; интерактивные зоны мелкие.
- Связи — прямые линии без визуальной иерархии; после роста графа читать их трудно.
- Начальная демонстрационная сцена не связана с пользовательским сценарием и сбивает с толку.

### Интерфейс и обратная связь

- Нет панели проекта, подсказки следующего действия и видимого состояния режима API/демо.
- Ошибки и успех копирования показаны через `alert`, а часть ошибок видна только в консоли.
- Текст результата принудительно уменьшен до `0.65rem`; длинный текст трудно читать.
- Глобальные `!important`, фиксированные ширины и незакрытая структура CSS создают наложения и непредсказуемую вёрстку.
- Кнопки и поля не образуют единой системы; focus/selected/disabled состояния непоследовательны.
- На обычном экране нижняя часть исходного узла сценария почти касается границы окна.

### Код и надёжность

- Исходный lint: 8 ошибок и 1 предупреждение; production build при этом проходит.
- Получение актуального состояния через `setState` + `setTimeout(0)` хрупкое и дублируется во всех генераторах.
- Нет отмены запроса и единого состояния ошибки; повторные действия могут создавать дубликаты.
- `NodeData` — набор несвязанных optional-полей без версии документа и проверки импортируемых данных.
- Object URL изображений не переживает перезагрузку, но освобождается не во всех жизненных циклах.
- Error Boundary отсутствует.
- README описывает Zustand и Konva, которых в фактической архитектуре приложения нет, и не содержит актуального запуска без API.

## Приоритет исправлений

1. Ввести версионированный документ проекта и безопасный тестовый режим без API.
2. Починить основной путь, валидацию, ошибки и защиту от повторной генерации.
3. Пересобрать взаимодействие канвы: pan, zoom, fit, drag, selection, delete, resize и предсказуемую раскладку.
4. Унифицировать интерфейс и доступные состояния.
5. Добавить localStorage, JSON-экспорт/импорт, новый проект и подтверждённый сброс.
6. Обновить документацию и полностью проверить GitHub Pages-пути.

## Что сознательно не входит в этот этап

- Производственный конвейер видеоманхвы, аккаунты, облачная БД и совместная работа.
- Полноценные библиотеки персонажей/локаций и управление эпизодами.
- Хранение тяжёлых изображений в `localStorage`.

Структура документа должна оставить расширяемые метаданные и стабильные идентификаторы, чтобы позже добавить персонажей, локации, эпизоды, сцены, производственные статусы, изображения и motion-промпты без миграции всей канвы.
