# CANVA STORY

CANVA STORY — локальная визуальная мастерская для разработки сценария. Пользователь вводит исходный текст, задаёт количество сцен и получает связанный граф: визуальный сценарий, сцены, описания героев, локаций и настроения, а затем text-to-image промпты.

Приложение сохраняет проект в браузере и работает без внешнего API на встроенных тестовых данных. Это стабильная основа существующего проекта, а не отдельный прототип конвейера видеоманхвы.

## Что умеет приложение

- превращать исходный текст в заданное количество сцен;
- создавать и обновлять карточки героев, локаций и настроения;
- собирать англоязычный визуальный промпт для отдельной сцены;
- строить ассоциативные ветки для слова или образа;
- перемещать и изменять размер нод;
- панорамировать канву и масштабировать её вокруг курсора;
- центрировать граф и показывать весь проект;
- выделять и каскадно удалять ноды с подтверждением;
- автоматически сохранять проект в `localStorage`;
- экспортировать и импортировать версионированный JSON;
- создавать тестовый кадр без внешнего API.

## Быстрый запуск

Требуется Node.js 20 или новее.

```bash
git clone https://github.com/olyyarm/CANVA_STORY_.git
cd CANVA_STORY_
npm ci
npm run dev
```

Откройте адрес, который покажет Vite, обычно `http://localhost:5173/CANVA_STORY_/`.

На Windows после установки зависимостей можно также запустить `start.bat`.

## Работа без API

Никакая настройка не нужна. Если `VITE_MISTRAL_API_KEY` отсутствует, приложение автоматически включает тестовый режим. Он проходит весь основной путь и создаёт предсказуемые локальные данные без сетевых или платных генераций.

Для явного включения режима скопируйте `.env.example` в `.env`:

```env
VITE_MOCK_MODE=true
VITE_MISTRAL_API_KEY=
```

## Локальное подключение Mistral

В локальном `.env`:

```env
VITE_MOCK_MODE=false
VITE_MISTRAL_API_KEY=your_local_key
```

Поддерживаются проверенные псевдонимы `mistral-small-latest` и `mistral-large-latest`.

Важно: Vite встраивает все переменные `VITE_*` в клиентский JavaScript. Такой ключ виден пользователю сборки и не является секретом. Не добавляйте реальный ключ в публичный GitHub Pages deploy. Для безопасного production-подключения нужен серверный proxy — это отдельный следующий этап.

## Локальное подключение LM Studio

В верхней панели приложения есть переключатель режима генерации: «Тест», «Mistral API» и «LM Studio». При выборе LM Studio появляются поля endpoint и model.

По умолчанию используется:

```text
http://localhost:1234/v1/chat/completions
```

Если LM Studio запущен на другом домашнем компьютере, укажите адрес этой машины в локальной сети, например:

```text
http://192.168.1.10:1234
```

Приложение само добавит `/v1/chat/completions`, если указан только базовый адрес. В поле model впишите имя модели, загруженной в LM Studio. Настройки сохраняются в браузере локально.

## Основной рабочий путь

1. В ноде «Исходный сценарий» введите текст.
2. Укажите от 1 до 20 сцен и при необходимости стилистическое направление.
3. Нажмите «Создать сцены». Канва автоматически покажет результат целиком.
4. В ноде визуального сценария создайте «Герои», «Локации» и «Настроение».
5. В нужной сцене нажмите «Собрать визуальный промпт».
6. Скопируйте промпт или создайте тестовый кадр.

Кнопка текущей генерации превращается в «Отменить». Готовые данные при отмене не удаляются.

## Канва

- перетаскивание фона — панорамирование;
- колесо мыши — масштаб вокруг курсора;
- перетаскивание заголовка ноды — перемещение;
- маркер в правом нижнем углу — изменение размера;
- `Delete` / `Backspace` — запрос на удаление выбранной ноды;
- `Esc` — снять выбор или закрыть подтверждение;
- «Показать всё» — вместить проект в рабочую область;
- «Центр» — центрировать проект, сохранив масштаб.

## Сохранение, экспорт и импорт

Автосохранение выполняется локально примерно через полсекунды после изменения. В верхней панели виден статус сохранения.

JSON-документ имеет `schemaVersion: 1`, стабильный `id`, метаданные проекта, ноды, viewport и секцию `extensions`. В `extensions` оставлены точки расширения для персонажей, локаций, эпизодов и ассетов.

Изображения, `blob:` URL, loading-состояния и временные ошибки не записываются в `localStorage` и не попадают в JSON. После перезагрузки или импорта кадр при необходимости создаётся заново.

«Новый» создаёт чистый проект с новым id. «Сброс» дополнительно очищает локальную копию. Оба действия требуют подтверждения.

## Структура

- `src/App.tsx` — оболочка проекта, канва и действия пользователя;
- `src/components/NodeRenderer.tsx` — содержимое и состояния нод;
- `src/hooks/useNodeManagement.ts` — основной сценарий и операции генерации;
- `src/hooks/useCanvasNavigation.ts` — pan, zoom, fit и center;
- `src/hooks/useDraggableNodes.ts` — drag, selection и resize;
- `src/api.ts` — выбор тестового, Mistral или LM Studio-режима;
- `src/mockData.ts` — локальные тестовые ответы;
- `src/project.ts` — схема v1, localStorage, экспортная очистка и проверка импорта;
- `AUDIT.md` — исходный аудит;
- `CHANGES.md` — результат текущего этапа.

## Текущие ограничения

- это однопользовательское браузерное приложение без backend и облачной синхронизации;
- публичное безопасное подключение AI требует server-side proxy;
- изображения не сохраняются в документе проекта;
- семантические библиотеки персонажей и локаций, эпизоды, production-статусы и motion-промпты пока представлены только точками расширения данных;
- полноценный режим видеоманхвы в этот этап не входит.
